# 顾客续住

顾客在“我的订单 → 查看详情”中，只有订单处于 `CHECKED_IN/PAID` 时能看到“续住”。选择新的退房日期，先计算新增晚数、总费用和库存，再确认续住。费用按新增每晚房价之和乘以房间数计算。当前项目的续住费用采用模拟支付，确认后在 `payment` 中保存一笔 `MOCK/SUCCESS` 流水；支付宝沙箱续住付款尚未接入。

后端客户接口保持原路径 `POST /api/v1/customer/stay/preview` 和 `POST /api/v1/customer/stay/extend`，请求 JSON：

```json
{"orderId": 30, "newCheckOutDate": "2026-10-20"}
```

确认时服务端核对 JWT 用户与订单归属，在事务中锁定订单和新增日期库存，复查价格与可售数量，使用 Redis 原子锁库存，然后更新 MySQL `sold_qty`、订单日期与金额并写支付流水。数据库回滚时补回 Redis 库存。STAFF 的原有接口路径保持不变，并使用相同的库存及计费修正。无需数据库迁移。

## 前端测试

1. 用 CUSTOMER 创建并支付订单，STAFF 为订单办理入住。
2. 确保原退房日期之后至少一天有房价、房量记录，并已将 MySQL 库存同步到 Redis。
3. CUSTOMER 打开“我的订单 → 查看详情 → 续住”，选新日期，点击“计算费用”。多间房时确认金额为新增房价乘房间数。
4. 点击“确认续住并模拟支付”，检查订单退房日期、晚数、金额变化；在 `payment` 查看新增 `MOCK/SUCCESS` 流水，`room_inventory.sold_qty` 在新增日期按房间数增加。
5. 使用另一位 CUSTOMER 的 JWT 调用该订单预览或确认接口，均应返回 404；重复提交旧日期应失败，库存不能重复扣减。

测试命令：后端 `mvn test`，前端 `npm run build`。如果 Redis 库存未初始化，确认接口会提示无法续住，此时使用项目现有 ADMIN 测试接口同步库存后再试。
