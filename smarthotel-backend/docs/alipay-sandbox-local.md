# SmartHotel 本机支付宝沙箱支付教程

这套操作不需要购买域名，也不需要先设置支付宝控制台的“授权回调地址”。付款后由后端主动查询支付宝交易，确认成功才更新酒店订单。不要照搬旧教程中“浏览器跳转后直接把订单改为已支付”的做法。

## 你需要准备

在支付宝开放平台的沙箱应用中，确认已选择**公钥模式**，并取得：沙箱 AppID、应用私钥、支付宝公钥、沙箱买家账号。把**应用私钥**和**支付宝公钥**分别保存为 UTF-8 文本文件，放在项目目录之外，例如：

```text
C:\Users\32273\alipay-keys\app-private-key.txt
C:\Users\32273\alipay-keys\alipay-public-key.txt
```

应用公钥用于上传到支付宝平台；后端 `ALIPAY_PUBLIC_KEY_FILE` 指向的是**支付宝公钥**。不要把私钥写入 `application.yml`、`.env.local`、聊天或 Git。

## 第 1 步：设置 IDEA 后端运行配置

打开 IDEA 右上角的后端运行配置 → **Edit Configurations…** → 选择 `SmarthotelBackendApplication` → **Environment variables**。每项单独添加一行：

| Name | Value |
| --- | --- |
| `ALIPAY_ENABLED` | `true` |
| `ALIPAY_APP_ID` | 你的沙箱 AppID |
| `ALIPAY_PRIVATE_KEY_FILE` | 应用私钥文件的完整路径 |
| `ALIPAY_PUBLIC_KEY_FILE` | 支付宝公钥文件的完整路径 |

本机测试时 `ALIPAY_NOTIFY_URL` **留空或不设置**。`ALIPAY_GATEWAY` 使用项目默认的沙箱网关即可。保存后停止并重新启动后端。

## 第 2 步：设置前端

在 `smarthotel-frontend` 目录新建 `.env.local` 文件，内容只有：

```text
VITE_ALIPAY_ENABLED=true
```

保存后停止并重新启动前端。`.env.local` 已被项目忽略，不会随代码提交。

## 第 3 步：实际测试

1. 用顾客账号登录，创建**新订单**，在支付倒计时结束前进入订单详情。
2. 点击“支付宝沙箱支付”，浏览器会打开沙箱支付页面。若弹窗被拦截，允许该站点弹窗后重试。
3. 使用**沙箱买家账号**付款，不要使用真实支付宝账号。
4. 回到原来的订单详情页，点击“我已完成付款，查询支付结果”。若支付宝尚未同步，可稍等数秒再点一次。
5. 页面显示付款确认后，订单应为 `CONFIRMED / PAID`；管理员支付记录中应出现 `ALIPAY / SUCCESS` 和支付宝交易流水号。

付款成功后不会自动跳回酒店网页；手动回到原订单标签页即可。不要对同一笔订单再点“模拟支付”。

## 常见问题

- **提示“支付宝沙箱尚未启用”**：检查 IDEA 环境变量，确认已重启后端。
- **仍显示“模拟支付”**：检查 `.env.local` 文件位置与内容，确认已重启前端。
- **提示密钥文件无法读取**：`ALIPAY_PRIVATE_KEY_FILE` 和 `ALIPAY_PUBLIC_KEY_FILE` 的值必须是现有文件的完整路径，不能直接粘贴密钥或公钥内容。前者使用应用私钥文件，后者使用支付宝公钥文件。
- **付款成功，但查询提示支付宝公钥配置错误**：在支付宝沙箱应用的加签管理中复制“支付宝公钥”，替换 `ALIPAY_PUBLIC_KEY_FILE` 指向文件的内容。应用公钥只用于上传到支付宝平台；不要用它验证支付宝返回的交易。修正后回到原订单查询支付结果，不要再次付款。
- **查询显示尚未付款**：确认在沙箱页面真正完成付款，并稍后再查询。
- **提示订单已取消或状态异常**：不要反复创建支付，联系管理员核对订单与支付记录；特别注意支付倒计时。

当前本机流程无需数据库迁移，沿用 `payment` 表。未来部署到公网后，可另行配置 `ALIPAY_NOTIFY_URL=https://你的域名/api/v1/payment/notify` 来启用异步通知；它与支付宝控制台的“授权回调地址”不是同一项。
